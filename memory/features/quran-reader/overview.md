# Feature: Quran Reader

## Purpose

Read the Quran (Arabic + English translation) by Surah, Juz, or Mushaf Page,
with per-ayah audio recitation playback, Continue Reading, and reading
progress tracking ("Quran 2.0 — Phase 1: Core Reading Experience"). This is
the feature that the tajweed coaching feature (see
`memory/features/tajweed/overview.md`) will attach to.

## Architecture

- **Data (text)**: `lib/features/quran/data/quran_local_repository.dart` —
  Hive-backed `SurahSummary` (114 rows) and `AyahRecord` (surah/ayah/Arabic/
  English text), seeded once from `assets/raw/quran_paak.json` +
  `assets/raw/english_translation.json`. Seed versioning via
  `StorageService.quranSeedVersion`. Phase 1 added `getAllAyahs()` and
  `getAyahsByKeys()` for Juz/Page lookups — no schema change, no seed bump.
- **Data (Mushaf layout)**: `assets/quran/uthmani.json` — per-ayah
  page/juz mapping for the standard 604-page Madani Mushaf, generated by
  `tool/generate_quran_metadata.py` from Tanzil's official structural
  metadata. See `assets/quran/README.md` for schema/regeneration/licensing,
  and `memory/decisions/ADR-001-reading-engine-and-mushaf-data.md` for why.
  Loaded/indexed at runtime by
  `lib/features/quran/reading_engine/mushaf_metadata.dart`.
- **Reading Engine**: `lib/features/quran/reading_engine/reading_engine.dart`
  — a `ChangeNotifier` shared by all three modes (Surah / Juz / Page). Given
  a mode + unit number, it resolves the ayah list (via the repository +
  mushaf metadata), tracks the current position, and debounced-persists
  Continue Reading + Reading Progress via `StorageService`. It owns neither
  audio nor rendering.
  - `lib/features/quran/reading_engine/reading_mode.dart` — `ReadingMode`
    enum (surah/juz/page).
  - `lib/features/quran/reading_engine/quran_audio_controller.dart` +
    `quran_repeat_mode.dart` + `quran_recitation.dart` — shared audio
    speed/volume/repeat wrapper and CDN URL builder for the Juz/Page
    screens.
- **Reusable UI**: `lib/features/quran/view/widgets/` — `AyahCard` (ayah
  rendering), `QuranAudioBar` + `showQuranAudioSettingsSheet` (bottom audio
  bar with speed/volume/repeat), `ContinueReadingCard`.
- **Surah Mode**: `lib/features/quran/view/quran_tab_screen.dart` (home,
  mode selector + Continue Reading card) →
  `lib/features/quran/view/surah_detail_bottom_sheet.dart` (unchanged
  rendering/audio; Phase 1 added a `ReadingEngine` purely for Continue
  Reading/progress tracking, plus speed/volume/repeat + prev/next-ayah, via
  the shared `QuranAudioBar`).
- **Juz Mode**: `lib/features/quran/view/juz_list_screen.dart` (30 Juz) →
  `lib/features/quran/view/juz_reading_screen.dart` (uses `ReadingEngine`
  fully — content, navigation, and tracking).
- **Page Mode**: `lib/features/quran/view/mushaf_page_screen.dart` — swipeable
  `PageView.builder` over all 604 pages, ayahs preloaded and grouped by page
  once (one Hive scan) for jank-free swiping; `ReadingEngine.trackPageVisit`
  is used for Continue Reading/progress since content bypasses
  `openPage()` for performance.
- **Reading Settings**: `lib/features/quran/view/reading_settings_screen.dart`
  — Arabic/translation font size, line spacing, default mode, remember last
  position. Backed by new `StorageService` keys (fonts reuse the existing
  `quranArabicFontSp`/`quranEnglishFontSp` keys).

## Key design decisions

- Quran text/translation ship as bundled JSON assets, not fetched at runtime
  — the app must work fully offline for reading (recitation *audio* streams
  remotely today; this is a gap for the offline tajweed feature to be aware
  of — the tajweed feature must not depend on that remote audio path).
- Mushaf page/juz numbers are real, standard Madani Mushaf numbers (sourced
  from Tanzil's official metadata, not app-invented pseudo-pagination) — see
  ADR-001. Page rendering is text reflow with the app's own typography, not
  scanned images.
- Surah detail is reached via imperative `Navigator.push`, not go_router —
  see `memory/technical-debt.md` TD-003. Juz/Page screens follow the same
  imperative-push convention for consistency (not a new pattern).
- Existing Surah screen's rendering/audio internals were intentionally left
  untouched; new capabilities were layered on via shared widgets/services
  rather than a refactor, per explicit "extend, don't rewrite" direction.

## Known issues

- No tajweed/pronunciation feedback exists in this screen today — that's the
  gap `memory/features/tajweed/` fills.
- Continue Reading position updates on ayah tap and on audio playback
  advancing to a new ayah, not on pure silent scrolling — acceptable for
  Phase 1, tracked informally (revisit if user feedback wants scroll-based
  tracking).
- See TD-003 in `memory/technical-debt.md`.

## Roadmap

Phase 1 (Surah/Juz/Page reading modes, Continue Reading, Reading Progress,
Reading Preferences, audio speed/volume/repeat, better navigation) is done.
Explicitly out of scope for Phase 1 (per spec): AI Tajweed/scoring,
Reflection Journal, translation downloads, multiple scripts/reciters, Quran
Journey, achievements, analytics. Tajweed attaches later per
`memory/features/tajweed/coreml-ios-integration-plan.md` Phase D.
